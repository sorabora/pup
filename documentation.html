    variables

    You can declare variables by using the local keyword. 

    local x = 10
// no semi colons are needed

    Which can be set to new values

    local x = 10
x = 20

    But if you want to do operations on them like addition, subtraction, etc you can do this 

    local x = 10
x += 1
/*
x += 1
x -= 1
x *= 1
x /= 1
*/
// would output 11...

    operators

    Operators are used to perform operations on variables.

    local x = (5 / 10) * 5 + 2
// would output 4.5

    conditional statements

    Conditional statements are used to check if a condition is true or false, then execute that code inside the block. 

    local x = 9
if x > 10:
  print("x is greater than 10")
else:
  print("x is less than or equal to 10")
end

    functions

    Functions are used to group code together and reuse it.

    function add(a, b):
  return a + b
end

add(1, 2) // would output 3

    loops

    Loops are used to repeat code multiple times.

    for i = 0, 100, 10:
  // 0 to 100... increment by 10 each time
end

    While loops too

    local x = 0

while x < 5:
  x ++
  // increments
end

    comparisons

    Comparisons are used to compare two values and return a boolean value. 

    include console

local x = 10
local y = 20

if x > y:
  print("x is greater than y")
end

if x < y:
  print("x is less than y")
end

if x == y:
  print("x is equal to y")
end

if x != y:
  print("x is not equal to y")
end

if x >= y:
  print("x is greater than or equal to y")
end

if x <= y:
  print("x is less than or equal to y")
end

if x != y:
  print("x is not equal to y")
end

    logical operators

    Logical operators are used to combine multiple conditions.

    and/&&, or/||, and not/! are exact aliases of one another — each pair compiles to the same operator, with the same precedence, so x > y and x < 30 and x > y && x < 30 are two spellings of the identical expression. Pick whichever style you (or your team) prefer; pup will never treat them differently. 

    include console

local x = 10
local y = 20

if x > y and x < 30:
  print("x is greater than y and less than 30")
end

if x > y or x < 30:
  print("x is greater than y or less than 30")
end

if not x > y:
  print("x is not greater than y")
end

if x > y && x < 30:
  print("x is greater than y and less than 30")
end

if x > y || x < 30:
  print("x is greater than y or less than 30")
end

if !(x > y):
  print("x is not greater than y")
end

    type safety

    pup's type checker is compile-time only. While you're editing, the transpiler statically analyzes your code and can flag type mismatches (e.g. passing a string where a function expects a number) directly in the editor gutter — but this checking is purely advisory and does not change the emitted JavaScript. Every type annotation is erased during transpilation; nothing about types is checked, enforced, or even present at runtime.

    This is the same tradeoff TypeScript makes relative to JavaScript: types exist to catch mistakes before you run your program, not to guard against bad values while it's running. Concretely, this means: 

    include console

function double(n)
  return n * 2
end

// The editor may warn you here at compile time...
local result = double("not a number")

// ...but nothing stops this from actually running:
// it happily executes with whatever value you pass,
// and any resulting bug (like NaN) only shows up as a
// runtime symptom, not a runtime type error.
print(result)

    If you need a value to actually be validated while the program is running (not just checked while you're writing it), you're responsible for writing that check yourself — pup does not insert any runtime guards on your behalf.

    html templates

    Besides building markup by calling html.el(...) piece by piece (see the html module), you can write HTML/XML literally as an expression — no quotes, no concatenation. Just start a tag with < and the parser reads it as one template value, up to its matching closing tag.

    Drop a variable into the markup with {{ name }}. It also accepts a dotted path like {{ card.value }} — anything more than a bare variable or property chain (no {{ a + b }}, no calls, no loops or if inside the template) isn't supported, so those still need a local computed beforehand. 

    include console

local name = "world"
local page = <div class="greeting">Hello, {{name}}!</div>

print(page)

    A template can span multiple lines as long as it's one balanced root element (tags opened inside it stay closed before the outer tag ends). Because there's no loop construct inside {{ }}, repeated markup (a hand of cards, a list of players, ...) still goes through html.list(items, renderFn) — build that piece as its own string, then splice it into the template like any other variable: 

    include console
include html

local hand = [
  { suit: "hearts", value: "A" },
  { suit: "spades", value: "K" }
]

function renderCard(card, i)
  return <div class="card">{{card.value}} of {{card.suit}}</div>
end

local cardsHtml = html.list(hand, renderCard)
local page = <div class="hand">{{cardsHtml}}</div>

print(page)

    Unlike html.text(), {{ }} does not escape its value — it drops the string straight into the markup. That's fine for your own data (like the examples above), but if a value might contain user input, escape it into a local first with html.text(...) or html.escape(...) and interpolate that instead, since {{ }} can't call a function directly.
